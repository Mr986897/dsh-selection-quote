# 引用选中（Selection Quote）

在会话里选中文字，浮出的「引用」按钮把选中的内容作为**引用胶囊（chip）**插入输入框：胶囊是编辑器里的单个原子节点，视觉上被包裹起来，不能被局部修改，鼠标悬停可看到完整引用内容。发送之后，这段引用在对话里也显示为**一张包裹好的引用卡片**，而不是一行行 `> ` 原文。

## 行为

- 在会话正文（Chat / Trajectory 视图）里拖选或键盘选中文字，选区末尾浮出小圆角按钮「引用」。
- 点击后输入框里出现一个胶囊，形如 `引用 · 助手 · 126 字 第一行 第二行 …`（超宽自动省略）。
- **不可修改**：胶囊是一个整体节点。光标无法进入内部，退格 / 删除一次删掉整块，选中时也只能整块选中。
- **悬停看全文**：胶囊的 `title` 就是它的标签文本，标签里带着摘要行 + 引用正文，所以鼠标停在上面会弹出全文（正文上限 1200 字，超出部分在末尾注明还剩多少字）。
- **发送后的样子**：消息里的引用段渲染成卡片——顶部是「引用 · 助手 / 引用 · 我」的窄条，下面是正文，整体一个圆角边框盒；卡片外的文字（你自己写的追问）照常按普通文本显示。
- **紧凑**：正文默认折叠到约 6–7 行（底部渐隐），只有真的溢出时才出现「展开（共 N 行）」，展开后可「收起」。两行的短引用不会出现这个按钮。
- **跳到原消息**：卡片标题条右侧有「跳到原消息」，点了会把对话滚到来源消息，并且**只把那段原文字本身**用绿色（系统绿 `#34C759`，36% 透明）高亮约 1.8 秒（不框整条消息）；找不到时按钮短暂显示「没找到原消息」。
- **发送的内容**：胶囊序列化成 markdown 引用块进入消息文本（模型看到的仍是标准引用块）：

  ```
  > 引用 · 助手
  > 第一行
  > 第二行
  ```

- 说话人按选中的消息行判定：user / steering / 追问 → 「我」，其余 → 「助手」。
- 插入后按钮位置短暂显示「已引用到输入框」，焦点交回输入框；被拒时显示「引用失败，请重试」。
- Esc 或点击别处收起按钮；滚动时按钮跟随选区。

## 配置

插件管理 → **插件**（Plugins）→ 本插件所在 bundle → 行 `selection-quote` 右侧的 **Configure**，打开本插件的配置页：

| 项 | 说明 |
| --- | --- |
| 引用样式 | `卡片`（默认，浅底 + 边框 + 标题条）/ `左侧竖线`（无底色，3px 竖线 + 缩进）/ `极简`（只留标题行与正文） |
| 高亮颜色 | 取色器 + 5 个预设（系统绿 #34C759、黄、蓝、橙、紫）+ 十六进制输入；只影响 `跳到原消息` 时原文字的底色 |
| 高亮时长 | 1.2 / 1.8 / 3 秒 |
| 折叠高度 | 4–24 em（页面同时显示≈多少行）；超过即截断并出现「展开」 |
| 跳到原消息按钮 | 显示 / 隐藏 |
| 恢复默认 | 一键回到默认值 |

页面带一个实时预览，改哪项立刻能看到卡片长什么样。所有项**即时生效**（不是暂存后保存）：改完直接关页面也不会丢，写进 `localStorage` 的 `dsh.selection-quote.v1`——只存在这台机器的浏览器里，换设备各管各的。样式表由插件自己持有（`style[data-plugin-css="selection-quote/styles"]`），设置变化时重写这张表，所以高亮色与折叠高度不需要任何全局 CSS 变量。

## 结构

| 文件 | 作用 |
| --- | --- |
| `client.js` | 全部 UI：`shell.overlay` 里的浮动按钮 + `conversation.input.overlay` 里的无渲染桥接 |
| `index.js` | Host 半身，只有空 `apply`，用于出现在插件清单 |
| `cordis.patch.yml` | 插入 `selection-quote` 行 |
| `locale/*.json` | 插件管理页的标题与描述 |

两处注册各有原因：

1. `inputActions`（`captureInsertion` / `insertText` / `setDraft`）只提供给会话作用域的槽位，所以桥接挂在 `conversation.input.overlay`（卡片内零高度锚点，不影响布局），把当前会话的输入框动词发布到模块级登记表。
2. 浮动按钮必须在位于所有列之上、又不受滚动容器裁剪的框架级图层，所以挂在 `shell.overlay`，读取登记表后调用插入；按钮不读写输入框 DOM。

胶囊的落地方式：桥接用 `ctx.sessions.scope(sessionId)` 拿到会话的 Agent 作用域，向编辑器投递它自己的 scoped 事件 `slash/input-insert-reference`（`@` 文件/会话引用走的是同一条通道），载荷是 `{ source, ref, label, appearance, clipboardText }`：

- `label` → 胶囊显示文本，同时是 `title`（悬停全文）；
- `appearance: 'quote'` → 未知图标种类按宿主实现不渲染图标，只留文字，避免借用文件 / 会话图标；
- `clipboardText` → 草稿文本投影（复制整段草稿时看到的内容）；
- `ref` → 引用正文本身（见下）。

### 为什么 ref 里放正文

发送时，输入框不是直接用 `clipboardText`，而是拿每个 chip 的 `source` 去输入管道要**序列化器**（`codec.serialize(ref)`），把 chip 段替换成 codec 的输出；没有 codec 就会拒绝提交并提示 `slash: no serializer for reference source "selection-quote"`（这就是旧版「引用好像没用」的原因——胶囊在，但一发送就被拒、草稿被复原）。

所以插件额外注册了一个只提供 codec 的引用源（`trigger: '@'`，`candidates` 恒为空，因此不会出现在 `@` 补全菜单里）。codec 收到什么就发什么，于是把正文直接放进 `ref`：不需要任何内存登记表或 localStorage，刷新后恢复的草稿仍然可发送。旧版留下的短 id chip 会在发送时替换成一行「旧版引用无法序列化，请重新选择后引用」，删掉重引即可。

### 发送后的卡片

对话里的用户消息由 UserText 规则管线渲染。插件注册了一条规则（`id: 'selection-quote'`，`order: 30`）：从光标位置找下一段**连续的 `> ` 行**，整段作为一个节点；首行若形如 `引用 · <role>` / `Quote · …` 就作为卡片标题，其余行作为正文（`white-space: pre-wrap` 保留换行）。然后在 `conversation.user.text.node` 上注册同名的 keyed 渲染器画出卡片。

- 匹配只认「行首的 `>`」，所以对话里 `a > b` 这种比较符不会误判；
- 两段引用之间夹着普通文字时，会各自成卡片，中间文字仍是文本；
- 你自己手打的 markdown 引用块同样会显示成卡片（没有标题条），语义一致；
- 规则先占位优先于引用块内部的 `@文件` 匹配：引用块被整段收进卡片，内部提及按纯文本显示。

卡片交互：

- **折叠**先渲染成 `data-clamped="1"`（`max-height: 9.5em` + 渐隐遮罩），再量 `scrollHeight > clientHeight` 决定是否给「展开」按钮——所以长短引用都不会误报；
- **跳到原消息**不依赖任何存档 id（消息里只有引用文本）：把正文前 3 行 + 后 3 行去掉 markdown 标记后各取 24 字做 needle，在 `[data-chat-flow-kind]` 行里**从当前消息往上**找最近的命中，`scrollIntoView({block:'center'})`。

  高亮只覆盖原文字，不覆盖消息盒子：先用 needle 在行内**换算回 raw 字符偏移**（`normalizeForMatch` 在压平文本的同时保留 index 映射），把首个命中点到最后命中行行尾之间用 `document.createRange()` 框成一个 Range，再用 CSS Custom Highlight API（`CSS.highlights.set('selection-quote-origin', new Highlight(range))` + `::highlight(selection-quote-origin){background-color:rgba(52,199,89,.36)}` 样式）着色，1.8 秒后删除。底色是系统绿 `#34C759`（截图里圆点的颜色）加 36% alpha，只设背景不设文字色；想更浓/更淡就改这一处的 alpha。这样高亮落在字形背后、跟随重排，不会碰到任何别人的 DOM，也不会改选区（因此不会误触发引用气泡）。

  旧消息若已不在 DOM 里（列表未挂载），按钮会显示「没找到原消息」；浏览器不支持 Highlight API 时只滚动、不画高亮。

样式统一由 `apply` 里注入的一张样式表提供（`style[data-plugin-css="selection-quote/styles"]`，随插件卸载移除），胶囊按钮和卡片共用，避免每条消息各挂一份 `<style>`。

空草稿没有可承载 chip 的段落，桥接会先落一个空格作为种子块，再插入胶囊；如果 codec 未注册（未挂载 ui-input-trigger）、事件通道不可用（未挂载 ui-conversation）、或插入抛错，一律自动退回纯文本引用块，功能不失效——因为只有 codec 就绪时才允许插入 chip，绝不会造出一个发不出去的胶囊。

## 调参

`client.js` 顶部：

- `MAX_CHARS`：进入消息文本的引用正文上限（4000）。
- `LABEL_CHARS`：胶囊标签 / 悬停 tooltip 的正文上限（1200）。
- `GAP` / `PILL_SPACE`：按钮与选区的间距，以及判断上方 / 下方放置的预留高度。
